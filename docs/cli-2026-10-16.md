# CLI usability and QA — 2026-10-16

The CLI now exposes a short workflow through `ink guide`, `train --from latest --for 30m`, `resume latest --for 30m`, `generate … -m latest`, `verify latest`, and `export latest`. [The README](../README.md) has complete commands and model-state explanations. This work did not start training, run backward passes or execute optimizer-update tests.

## Behavior

- Human durations accept seconds, minutes, hours and combinations. The old `--seconds`, `train --model … --resume`, `model verify`, and `skill export` forms remain supported.
- `train` creates a new version; `resume` continues the same version. Both support a shared read-only `--dry-run` preflight for source splits, corpus identity, vocabulary, recipe, checkpoint integrity, parent lineage and holdout isolation. It allocates no model and initializes no GPU runtime. Actual training uses the same preflight.
- `latest` explicitly selects a candidate. It never promotes an unapproved model or changes the default selection policy. Lookup walks newest-first and stops at a fully validated decoder. Model inventory checks manifest/file hashes; execution also validates neural tensor shapes.
- Generation and standalone inference now default to variation 0, matching the reviewed controlled-output instructions. `-m` and `-o` are convenient aliases. Seed reporting and unsupported-input failure-before-files remain intact.
- Verification shortcuts exit nonzero on recorded failures. Export requires a fresh output directory and prints a recovery command if a delivery already exists. Old model/corpus mismatches are explained before output creation.
- Data review, audit, doctor, model inventory and training plans print concise summaries. Successful training prints next commands using the new model's actual ID. Human runs report total elapsed time.
- `check` runs format checks, default tests and native all-target Clippy. Native tests that exercise optimizer updates require the explicit `--training-tests` switch. Child output is captured; failures go to stderr and do not contaminate JSON stdout.

## Progress

One presentation module supplies real count bars, phase-time bars and spinners. Sequence/auxiliary training bars show elapsed time, remaining estimate, updates and loss; preparation and saving have explicit labels. Verification counts actual completed requests, evaluation counts samples, and coverage counts original corpus rows. Export reports build, bundling and ZIP stages. Unknown totals use spinners rather than invented percentages.

Animation is on stderr only, defaults to attended terminals, and is disabled for redirected output, `TERM=dumb`, `--no-progress`, `--quiet` and `--json`. `--progress always` explicitly overrides terminal detection, but JSON/quiet still suppress animation. Plain stage messages are retained without animation; quiet suppresses those messages. An error abandons the current indicator rather than marking an operation successful. Progress is presentation only and does not change loss, weights, selection or stopping budgets.

## Epoch progress correction

Sequence training now redraws one batch-count bar for the current integer epoch and retains one summary line at its completion. Only that summary prints loss: the sample-weighted mean across the epoch's batches, including a smaller final batch. Ten-second loss messages and live batch-loss values are removed. The manifest records completed integer `epochs`, `epoch_batches_completed` and `batches_per_epoch`; raw final batch loss remains diagnostic metadata, not an epoch mean. The run trace records epoch summaries instead of ten-second batch snapshots.

Time budgets and deterministic batch selection are unchanged. A budget stop saves its partial epoch and displays its real batch position without loss. Resume starts from that position; the first completion omits loss if earlier batches were in the preceding process. Subsequent full epochs report means normally. The balanced glyph auxiliary has no corpus epoch, so its phase bar shows update counts without printing losses. Historical full-batch training reports one epoch per full-corpus update. Final human output no longer repeats raw losses outside epoch summaries.

The default workspace suite passed **27 tests**. Native all-target Clippy passed with warnings denied. Two synthetic reporting tests, using no model or optimizer, verify uneven batch weighting, resume boundaries and partial-stop counts. Real PTY and redirected-output captures exercise the production progress controller: exactly two complete-epoch means, one resumed completion with no mean and one partial stop at **1/3**, with no fractional epochs or batch-loss messages. The PTY exposed an Indicatif finish behavior that advanced partial bars to their total; the pause path now preserves the count, guarded by a regression assertion.
